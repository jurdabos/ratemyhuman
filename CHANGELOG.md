## [Unreleased]
### Changed
- Adopted the canonical non-truncating CLI help from acidbase: the top-level command group is now built with `acidbase.cli_utils.group` (a `click.Group` subclass) instead of `click.group`. Click's default group listing truncates each command's short help at 45 characters, so longer descriptions ended in `...`; the shared group wraps the full first paragraph onto aligned continuation lines instead. `RichGroup.main` also routes output through `ensure_unicode_safe_streams()`, so non-ASCII help (em dashes, accented words) survives on Windows consoles using a legacy code page. `uv.lock` pins acidbase at the commit providing `cli_utils`.
### Security
- `pyproject.toml`, `uv.lock`, `requirements.txt`: bumped torch to `>=2.13.0` (locked `2.13.0+cu130`, up from the `2.12.0.dev20260408+cu128` nightly) to clear `CVE-2025-3000`, with torchvision following in lockstep to `>=0.28.0` (locked `0.28.0+cu130`, the release paired with torch 2.13.x). `acidbase patch` failed on this repo with `UVADDFAIL` because `uv add` only rewrites `[project.dependencies]`, while the stale `[tool.uv] override-dependencies` floors (`torch>=2.12.0.dev,<2.13`, `torchvision>=0.27.0.dev,<0.28`) REPLACE the project's own requirements during resolution and kept `uv.lock` on the old nightly. Resolved manually by bumping both copies in lockstep (same failure mode as the earlier Pillow override bump below).
- `pyproject.toml`, `uv.lock`, `requirements.txt`: raised setuptools to `>=83.0.0` (locked and exported `setuptools==83.0.0`, up from `81.0.0`) to clear `CVE-2026-59890`. setuptools is only pulled in transitively via the cu128 torch nightly, whose wheel metadata caps setuptools below 83, so `acidbase patch` failed on this repo (`uv add` reported `setuptools>=83.0.0` and `torch==2.12.0.dev20260408+cu128` as unsatisfiable). Resolved manually by adding a `setuptools>=83.0.0` floor to `[project.dependencies]` and mirroring it in `[tool.uv] override-dependencies`; the override REPLACES torch's own setuptools requirement during resolution (the same lockstep pattern documented for the Pillow floor). torch / torchvision stay pinned at `2.12.0.dev20260408+cu128` / `0.27.0.dev20260407+cu128`.
- `pyproject.toml`, `uv.lock`, `requirements.txt`: raised the Pillow floor in `[tool.uv] override-dependencies` from `>=12.2.0` to `>=12.3.0` and re-locked / re-exported so the resolved install is `pillow==12.3.0`. The previous bump commit only moved the `[project.dependencies]` specifier: uv overrides REPLACE the project's own requirement during resolution, so the stale `pillow>=12.2.0` override kept `uv.lock` and the `requirements.txt` export at 12.2.0 and the 26 open Dependabot Pillow alerts (13 advisories, all first patched in 12.3.0, incl. `CVE-2026-59200`) unresolved. The two pillow floors must stay in lockstep, per the comment above the override block.
- `pyproject.toml`, `uv.lock`, `requirements.txt`: raised the Pillow floor to `>=12.2.0` and refreshed the generated lock / export so runtime installs use `pillow==12.2.0`. This clears the Dependabot-reported Pillow range `>=11.2.0,<11.3.0` (`CVE-2025-48379`, high) and `CVE-2026-25990` (high); the `>=12.2.0` floor also keeps the project aligned with the broader repository-wide Pillow bump.
### Fixed
- `tests/test_cli.py`: repaired test collection, which crashed with `ImportError: cannot import name '_auto_commit_message' from 'ratemyhuman.cli'`. The push workflow (and its private helpers) had been extracted to the shared `acidbase.push` module — `ratemyhuman/cli.py` now only registers `push_command` — but the tests still imported the helpers from `ratemyhuman.cli` and patched `ratemyhuman.cli._*` targets. Imports and `unittest.mock.patch` targets now point at `acidbase.push`, keeping consumer-side contract coverage of the shared workflow. Adjusted for two API changes: `_get_project_root` became public `get_project_root` (pyproject.toml-only root discovery, no `.dvc/` marker), and the push-workflow tests explicitly patch the new `has_dvc` gate (`return_value=True`) so DVC branches are exercised deterministically regardless of a local `dvc` install.
### Changed
- `pyproject.toml`, `uv.lock`, `requirements.txt`: migrated torch/torchvision from the `nightly/cu128` index to the stable CUDA 13.0 index (`https://download.pytorch.org/whl/cu130`; index renamed `pytorch-cu128` → `pytorch-cu130`). Stable cu128 stops at torch `2.11.0`, so the CVE-2025-3000 floor cannot be met on it, and the nightly channel is no longer needed now that stable cu130 wheels cover Blackwell GPUs. Also marked the index `explicit = true` and dropped `index-strategy = "unsafe-best-match"`, mirroring the tcnvsrnn/transcriber index hardening, so uv no longer fans out to `download.pytorch.org` for unrelated packages. The locked CUDA runtime moved from `nvidia-*-cu12` to CUDA-13 builds, and triton from the nightly `3.7.0+git282c8251` to stable `3.7.1`.
- `tests/test_cli.py`: moved the 22 helper unit tests (classes `TestHooksModifiedFiles`, `TestAutoCommitMessage`, `TestGetProjectRoot`, `TestHasChanges`, `TestFindUntrackedForDvc`, `TestFindDvcChangedOuts`) upstream to acidbase `tests/test_push.py`, where the helpers are owned — they previously had no coverage in that repo. test_cli.py now covers only the ratemyhuman CLI wiring plus push-workflow contract tests run through this repo's CLI entry point, and no longer imports any private `_`-names from `acidbase.push` (string patch targets remain), so upstream internal refactors can no longer break this repo's test collection. Suite after the move: 88 passed, 3 slow deselected (110 − 22 moved).
- `pyproject.toml`, `uv.lock`, `requirements.txt`: replaced brittle exact PyTorch nightly pins (`torch==2.12.0.dev20260324+cu128`, `torchvision==0.26.0.dev20260324+cu128`) with durable cu128 nightly ranges (`torch>=2.12.0.dev,<2.13`, `torchvision>=0.27.0.dev,<0.28`) while keeping `[tool.uv.sources]` routed to the `pytorch-cu128` index. `uv.lock` now pins currently available wheels (`torch==2.12.0.dev20260408+cu128`, `torchvision==0.27.0.dev20260407+cu128`), so clean checkouts can resolve and sync again even after PyTorch has rotated the older nightly wheels off the index.
